Linear delivery metrics across every team in the workspace.

What is outstanding, what the running cycles look like, and whether issues are
being closed faster than they arrive.

    linear [-n SECONDS] [team-key ...]

Team keys are the prefixes on issue identifiers - XFY, SYS and so on. With
none given every team is included, minus anything in `linear.exclude_teams`.

Triage is counted apart from the backlog throughout. An auto-filed intake
queue and a groomed backlog are different populations, and adding them
together produces a number that means nothing.

Several linear panes on one machine share what Linear answers: one pane walks
the workspace each refresh and the rest draw their own teams from its answer.
A line under the status line says which pane fetched it and how long ago. The
answers, issue titles included, are kept in a file only you can read. Cleanup
rides on a later save after 2 hours without a publication, not on a deadline;
`linear.share_readings` false keeps this pane to itself but does not delete an
existing file. A rate limit stops every pane using that key, project screens
included, until the time Linear named - or, when it named none, for two
minutes, doubling while limits keep coming - and each says when it asks again.

Credentials: `linear.token` in config.json, or $LINEAR_API_KEY. A personal API
key from Settings - Security & access - Personal API keys. The API is called
directly, so no CLI is required.

Keys: tab focuses a pane — the cycles, then the teams, then no focus at all —
and up/down move the cursor in whichever is focused, leaving it if you walk off
either end. r refreshes now, w cycles the window (7/14/30/60/90 days), comma opens
settings, q quits.

Press ! to read this widget's notices - warnings that are not about a number on
screen, such as a config file others can read or a recommended tool that is
missing - and dismiss them for this session, for 7 days or for 30. A new notice
shows under the footer for a minute, and a [!] count stays on the top row for
as long as it is still true. Clicking the count opens the same screen.

ctrl-y and ctrl-e scroll the view a line at a time, as in vim, and the
mouse wheel does the same. They move the pane and never the selection,
which is what the arrows are for.
