Which processes are using the network, how much, and how fast.

Linux reads per-socket TCP counters from `ss -tine` and joins their inodes to
/proc/<pid>/fd. macOS has no per-socket equivalent, so it reads all-protocol
per-process totals from `nettop`. The pane names which measurement its rows
carry. Neither needs packet capture, a kernel module, or root.

    netwatch [-i SECONDS] [-n COUNT] [--sort total|live]
             [--external] [--plain]

On Linux, only traffic that leaves the machine is counted. --external narrows
that to internet peers. Per-process nettop output has no peer field, so macOS
cannot apply that filter and says so in the pane and README.

Totals start at zero: the first sample is a baseline and only what happens
after it is counted. A process that exits keeps what it used, marked so, since
"what has been eating the connection" is usually asked after the thing has
stopped.

Linux process rows are TCP only. macOS process rows include every protocol.
See the netwatch README for the platform contract.

Enter opens one process. Linux can show attributed endpoints and connections;
macOS marks those unavailable because nettop provides only process totals.
Both show command and open files where the OS permits it. The URL and remote
filename remain inside TLS.

Keys: up/down select, enter opens one, esc goes back, 1 sorts by total,
2 by current rate, o shows the daemons you do not own, r rezeroes,
comma opens settings, q quits.

ctrl-y and ctrl-e scroll the view a line at a time, as in vim, and the
mouse wheel does the same. They move the pane and never the selection,
which is what the arrows are for.
