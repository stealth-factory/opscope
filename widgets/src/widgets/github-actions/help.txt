GitHub Actions runs, failures and queue time.

What is running right now, which workflows are failing repeatedly, which job
and step broke, and how long the pipeline is taking — across your personal
repos and every org you belong to, using the same token github and github-prs
already hold.

    github-actions [-n SECONDS] [owner/repo ...]

Polls every 60s by default (-n changes it, minimum 30s). Extra arguments are
repos to watch; with none given it uses `github_actions.repos`, and failing
that the most recently pushed repos that have workflow files, capped per owner.
Empty `github_actions.accounts` discovers your login and every org you belong
to.

Credentials: `github_actions.token` in config.json, or the variable named by
`token_env` (`$GITHUB_TOKEN` when that key is unset).
`github_actions.token` / `github_actions.token_env` override that when set.
A classic token with `repo` and `read:org`, the same one github uses. This
widget only reads. An old `gha` section is still read if `github_actions` is
absent, and the pane says so.

GitHub Enterprise: set `enterprise_hostname` to the web host, for example
`acme.ghe.com`, and requests go to `https://api.acme.ghe.com`; any other
host but github.com or api.github.com is treated as Enterprise Server
(untested). Or name a variable in
`enterprise_hostname_env` and set the host there; none is read unless named.
The token must come from that host.

Keys: up/down select a run, Enter opens its jobs, r refreshes now, s cycles
the state filter (all / failed / running), / filters by text against the
repo, workflow, branch, event, conclusion and title, w cycles the window
(12h / 24h / 48h / 7d), comma opens settings, q quits. On a run, c copies
its URL, esc closes.

Press ! to read this widget's notices - warnings that are not about a number on
screen, such as a config file others can read or a recommended tool that is
missing - and dismiss them for this session, for 7 days or for 30. A new notice
shows under the footer for a minute, and a [!] count stays on the top row for
as long as it is still true. Clicking the count opens the same screen.

ctrl-y and ctrl-e scroll the view a line at a time, as in vim, and the
mouse wheel does the same. They move the pane and never the selection,
which is what the arrows are for.
